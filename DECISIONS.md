# DECISIONS — примерка дисков

Где в ТЗ был выбор, решение принято самостоятельно. Ниже — что выбрано и почему.

## 1. Заявки: способ 1 (Telegram-бот + Cloudflare Worker) с запасным способом 3 (deep link)

- **Выбран способ 1**, как рекомендовано в ТЗ. Воркер написан и проверен: `worker/src/index.js`, тесты `npm run test:worker` (5 сценариев на замоканном Telegram API: текст, фото multipart, чужой origin, лимит 5 заявок в минуту с IP, отказ Telegram → 502).
- Форма шлёт JSON и превью примерки в JPEG. Размер ужимается ступенями до ≤ 300 КБ, в тесте вышло 58 КБ. Это проверяет e2e-тест «lead via Worker».
- **На демо сейчас работает способ 3 (deep link).** Бот-токена и аккаунта Cloudflare у меня нет, а выдумывать их нельзя. Включение воркера: задеплоить `worker/` и вписать адрес в `config/brand.json → leads.workerUrl`. Код страницы менять не нужно.
- Если воркер не ответил, страница сама открывает deep link с готовым текстом. Заявка не теряется.
- Без указанного аккаунта deep link ведёт в окно «Поделиться» Telegram (`t.me/share/url`), а не на чужой username. Иначе заявки демо могли бы уйти постороннему человеку. Для клиента: `contacts.telegram` или `leads.channel: "whatsapp"` + `contacts.whatsapp`.

## 2. Видео-референс (`reference/ref.mp4`, 43 кадра в `reference/frames/`)

Подробный разбор в `REFERENCE-NOTES.md`.

**Перенесено:**
- тёмный гараж-шоурум: панели на стене, световые полосы, лампы с дымкой, подиум-поворотный круг, мокрый пол с отражением машины;
- лента дисков `№01…№12` поверх сцены (быстрый выбор одним тапом);
- кнопки на сцене: «Как было», «Крупно», «В подборку»;
- вкладки «Гараж / Каталог»;
- «Гараж»: зона «Новый клиент» с drag & drop и сетка «В гараже»;
- каталог с номерами `№NN`, строкой `R19, 5×112, ET35` и ценой акцентом;
- режим «На машине»: каждый диск каталога отрисован на выбранной машине клиента (в референсе это «клиенты увидят свою машину с каждым»).

**Не перенесено, с причиной:**
- **Зелёный неон.** ТЗ прямо требует «без неона», акцент APEX — тёплый металлик. Свет в гараже тёплый. Любой цвет акцента ставится в `brand.json`.
- **360° и фотореалистичные ракурсы.** В референсе картинки генерирует нейросеть, а ТЗ требует Canvas 2D. Для 360° нужны снимки с нескольких ракурсов на каждую машину. Структура `cars.json` это позволяет, но в демо их нет.
- **Генерация промо-рилса.** Это отдельный сервис генерации видео, в ТЗ его нет.
- Название и фирменный стиль автора ролика не используются.

## 3. Стек

- **Vite 8 + TypeScript 7, ванильный TS без Preact.** 6 экранов и один Canvas-компоновщик не требуют фреймворка. Итог: JS 18.8 КБ gzip при бюджете 150 КБ.
- **Hash-роутинг** (`#/fit?car=…&wheel=…&d=…`). На GitHub Pages нет серверных редиректов. Заодно ссылка «Поделиться» открывает ту же примерку.
- **Конфиги грузятся во время работы** из `public/config` и `public/data`, а не вшиваются в сборку. Новый клиент = замена JSON и картинок, без пересборки. `?brand=имя` подгружает `config/brand.имя.json`: второй бренд можно показать на том же деплое (пример: `?brand=kolesa`).

## 4. Рендер (Canvas 2D)

- Порядок слоёв на каждое колесо: шина поверх штатного диска (цвет боковины берётся с фото) → тормозной диск и суппорт (цвет из `brand.colors.caliper`) → затемнение глубины обода → новый диск.
- Эффекты диска по ТЗ:
  - тень `rgba(0,0,0,0.35)` с размытием;
  - яркость ±25 %, подбирается автоматически по яркости колеса на фото;
  - тень сверху от арки;
  - зерно: сильнее на фото с телефона, слабее на студийных кадрах.
- Размер обода: `радиус шины × rimToTireRatio[диаметр]` (R16 0.58 … R22 0.78), таблица в `data/wheels.json`. Для отдельной модели можно задать свою.
- Смена диска: кроссфейд 200 мс и доворот 15°, ease-out. Спрайты дисков кешируются, картинки всего каталога подгружаются в простое. От тапа до первого кадра 6–23 мс (Playwright, лимит 150 мс).
- На демо-машинах новый диск отражается в полу, полосами с затуханием.
- «Крупно» плавно приближает переднее колесо. На телефоне иначе диск всего около 45 px.
- «Как было»: шторка до/после на Canvas. Ручка — доступный `role="slider"`: стрелки, Home/End.

## 5. Демо-ассеты

- **Диски:** 12 параметрических SVG (`scripts/wheel-shapes.mjs`): 5 спиц, сетка, монолит, турбина, Y-спицы, двойные спицы, аэро, 15 спиц, направленные, кованые с карманами, глубокая полка, чёрная сетка. У каждой спицы освещённая и затенённая грань, есть глубина, обод, болты и колпачок. В рантайме — WebP 1024×1024 с прозрачностью и превью 256 px в AVIF/WebP.
- **Машины:** 7 кузовов строго сбоку, сгенерированы скриптом (`scripts/gen-cars.mjs`). Готовых фото с понятной лицензией не было, а качать чужие снимки в публичное демо не стал. Это стилизованные рендеры, не фото. Для клиента их заменяют реальные снимки и разметка колёс в `cars.json`.
- **`scripts/prepare-wheel.py`:** фото диска → rembg (по умолчанию модель `u2net`) → центрирование → круг → 1024 PNG/WebP + превью. Проверены обе ветки: с rembg и `--no-rembg`.

## 6. Дизайн

- APEX: фон `#0A0B0D`, текст `#F2F2F2`, акцент тёплый металлик `#C9A878`. Это единственный акцент; зелёный цвет «в наличии» — служебный, статусный.
- Шрифты self-hosted через Fontsource, только кириллица и латиница: Tenor Sans для заголовков, Golos Text для интерфейса.
- По запретному списку агента `lera`: без капса с разрядкой, без точек-разделителей, без стекла на карточках (blur только у шапки, нижней панели и кнопок поверх фото) и без мёртвых серых кнопок.
- Mobile-first, 360–1440 px. Сцена с лентой дисков прилипает сверху, действия в нижней панели под большой палец, все кнопки ≥ 44 px, поля 16 px (iOS не зумит), `100dvh`, `viewport-fit=cover` и safe-area.

## 7. Персональные данные (152-ФЗ, чек-лист из SGX-материалов)

Галочка согласия отдельная и по умолчанию снята, рядом ссылка на политику. `public/privacy.html` — шаблон, который нужно заменить документом клиента. Своё фото обрабатывается только в браузере.

## 8. «В подборку»

Хранится в `localStorage` у посетителя. Если хранилище недоступно (приватный режим), подборка живёт в памяти. Подборка уходит вместе с заявкой.

## 9. Что не попало в публичный репозиторий

- `reference/ref.mp4` и `reference/frames/` — чужой ролик, оставлен локально.
- `.claude/` (копии скиллов SGX) и `docs/SGX-INVENTORY.md` (опись личных материалов) — локально. Список скиллов в `docs/SKILLS-USED.md` в репозитории есть.
